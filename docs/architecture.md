# 架构与数据流

## 目标与边界

BookLens 是单用户、自托管的 EPUB 阅读器。设计目标是少依赖、易部署、可回归：一个 FastAPI 进程负责书架、解析、搜索、阅读页和 AI 代理，浏览器只保存个性化状态。

项目不包含账号、跨设备同步、阅读笔记、划线和双页排版。生产入口的访问控制由 Cloudflare Access 提供，不等于应用层多租户权限。

## 组件

| 组件 | 职责 | 事实来源 |
| --- | --- | --- |
| `server.py` | FastAPI 路由、搜索、AI 上下文、安全约束、SSE 代理 | 服务端代码与 `tests/test_ai_context.py` |
| `reader3.py` | EPUB 解析、内容清洗、图片路径改写、pickle 持久化 | 解析代码与相关测试 |
| `templates/library.html` | 书架 | 模板 |
| `templates/import.html` | EPUB 上传 | 模板 |
| `templates/reader.html` | 阅读器、目录搜索、设置、AI 面板和浏览器状态 | 模板与 `tests/test_reader_ui.py` |
| `book/<book_id>_data/` | 解析后的 `book.pkl` 与图片 | 运行时数据，不进 Git |

## 阅读链路

1. `POST /api/upload` 接收 EPUB，并由 `reader3.py` 解析到 `book/`。
2. `GET /` 扫描 `*_data` 目录形成书架。
3. `GET /read/{book_id}/{chapter_index}` 从缓存载入书籍，渲染当前章节和目录。
4. 浏览器用 `localStorage` 保存阅读位置、字体、主题、AI 范围、聊天记录和自定义阅读分析提示词。
5. `GET /api/search-book` 在服务端检索标题与正文，浏览器只接收匹配章节和短摘要。

浏览器状态是便利功能，不是可靠数据层；清理站点数据、换浏览器或换设备会丢失这些设置。

## AI 问书链路

1. 浏览器提交问题、当前章节、范围、短聊天历史和可选分析提示词。
2. 服务端校验书籍、章节和范围。指定范围最多 12 节；全书模式最多选取 12 个相关章节，总上下文最多 400,000 字符。
3. 服务端把不可覆盖的安全约束、阅读分析方法、历史、检索原文和问题组装为消息。
4. 服务端携带环境变量中的 API Key 调用 DeepSeek；浏览器永远接触不到密钥。
5. 上游内容以 SSE 转换为稳定事件：
   - `token`：`{"content":"..."}`
   - `done`：`{"model":"deepseek-v4-pro"}`
   - `error`：`{"detail":"..."}`
6. 上游推理字段只用于维持连接，不发送到浏览器。

每个来源 IP 每小时最多 20 次 AI 请求，服务端最多并发 2 次。限制保存在进程内存中，重启会重置，多实例之间不会共享。

## 关键取舍

- 使用 pickle 简化单机持久化，但它不是不可信输入格式；不要载入外部提供的 `book.pkl`。
- 全文搜索是逐章内存扫描，适合个人书库；书量明显增长后再考虑索引，当前不引入数据库。
- 浏览器渲染的是轻量 Markdown 子集，不是完整 Markdown 引擎。
- `DEEPSEEK_MODEL` 是代码常量。供应商模型名或能力变化时，必须以实际 API 响应和测试为准。
